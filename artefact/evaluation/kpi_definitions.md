# KPI Definitions and Measurement Guide

**Version:** 1.0.0  
**Purpose:** Defines the four operational KPIs for the ILM artefact; specifies how each is measured in a production or test environment.

---

## KPI-1: Time-to-provision (T2P)

**Definition:** Elapsed time from receipt of a Joiner event to the moment the Okta user account reaches `Active` status with all baseline groups assigned.

**Formula:** `ilm_tx_log.completedAt − ilm_tx_log.createdAt`  
**Filter:** `eventType = joiner AND status = Completed AND ilm_accessPackage IS NOT NULL`  
**Exclude:** Rows where approval was required (approval wait = human latency, not workflow latency). Track approval-path separately as T2P-with-approval.

**Measurement source:** `ilm_tx_log` table  
**Reporting period:** Monthly  
**Report:** Median, 90th percentile, maximum  

**Target:** ≤ 15 minutes (automated path)  
**SLA breach threshold:** > 60 minutes on automated path (no approval)  

**Note:** Sandbox variability is expected to be ±30 seconds due to shared infrastructure. Production values will be lower.

---

## KPI-2: Time-to-revoke (T2R)

**Definition:** Elapsed time from receipt of a Leaver event to the moment the Okta user account is suspended (step L-3 completion).

**Formula:** `timestamp(user.lifecycle.suspend event in System Log) − ilm_tx_log.createdAt`  
**Filter:** `eventType = leaver`  
**Measurement source:** Okta System Log (query: `debugContext.debugData.requestId eq "{txId}"`, filter event type = `user.lifecycle.suspend`)  

**Why not ilm_tx_log.completedAt:** Account suspension occurs in step L-3, before the transaction's `completedAt` field is written. The System Log timestamp is the most precise available measure of when revocation took effect.

**Reporting period:** Monthly  
**Report:** Median, 90th percentile, maximum  

**Target:** ≤ 5 minutes for same-day events; ≤ 5 minutes from scheduled trigger fire time for future-dated events  
**SLA breach threshold:** > 30 minutes (flag for investigation)  

**Baseline for comparison (as-is):** 0–5 business days (manual notification chain)

---

## KPI-3: Transaction completion rate (TCR)

**Definition:** Proportion of lifecycle transactions reaching `Completed` status within the configured SLA window, across all JML event types.

**Formula:**
```
TCR = COUNT(rows where status = 'Completed' AND (completedAt - createdAt) <= SLA_window_hours * 3600)
      ÷ COUNT(all rows in period)
      × 100
```

**SLA window per event type:**

| Event type | SLA window |
|---|---|
| Joiner (automated) | 15 minutes |
| Joiner (with approval) | Approval SLA + 15 minutes |
| Mover (automated) | 30 minutes |
| Leaver (automated) | 60 minutes |
| Any (pending manual tasks) | Manual task SLA (per system class) |

**Rows in `Pending-intervention` beyond SLA window count as failures.**  
**Measurement source:** `ilm_tx_log` table  
**Reporting period:** Monthly  
**Report:** Overall TCR + breakdown by eventType  

**Target:** ≥ 95% within SLA window  
**Action threshold:** < 90% for any single event type triggers L2 investigation

---

## KPI-4: Manual task closure rate (MTCR)

**Definition:** Proportion of ITSM deprovisioning tasks generated by the Leaver flow that are closed within their configured SLA.

**Formula:**
```
MTCR = COUNT(tasks closed on or before due_date)
       ÷ COUNT(all tasks created by ILM service account in period)
       × 100
```

**Measurement source:** ITSM platform (query all tasks created by `ILM-Service-Connection` account)  
**Reporting period:** Monthly  
**Report:** Overall MTCR + breakdown by appOwnerItsm (to identify consistently slow owners)  

**Target:** ≥ 90% closed within SLA  
**Action threshold:** Any single app owner with < 70% closure rate for two consecutive months triggers escalation to their manager  

**Note:** Low MTCR is an organisational process indicator, not an automation failure. The artefact correctly generates and tracks tasks; closure is the responsibility of application owners.

## Measurement dashboard (recommended queries)

Run these queries monthly against `ilm_tx_log`:

```
// T2P - all automated Joiner completions this month
SELECT median(completedAt - createdAt), percentile90(completedAt - createdAt), max(completedAt - createdAt)
FROM ilm_tx_log
WHERE eventType = 'joiner' AND status = 'Completed' AND createdAt >= first_day_of_month

// TCR - overall
SELECT COUNT(*) FILTER (WHERE status = 'Completed') / COUNT(*) * 100 AS tcr
FROM ilm_tx_log
WHERE createdAt >= first_day_of_month

// Open interventions (operational health)
SELECT txId, eventType, employeeNumber, errorDetail, createdAt
FROM ilm_intervention_queue
WHERE status = 'open'
ORDER BY createdAt ASC

// Pending manual tasks > 48 hours old
SELECT txId, employeeNumber, itsm_tasks, createdAt
FROM ilm_tx_log
WHERE status = 'Pending-manual-tasks' AND createdAt < now - 48h
```
